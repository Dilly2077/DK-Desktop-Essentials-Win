02 Hardware Performance and Appearance Paywall Audit

DK'S DESKTOP ESSENTIALS  /  COMPETITIVE PAYWALL AUDIT
	02
Hardware, Performance & Appearance
Sensors, fan curves, RGB, ScreenSync, power/process profiles and startup controls



Purpose
A product-requirements audit of features that current public competitors restrict to paid editions, subscriptions, DLC, or post-trial licences. The aim is to identify features DK’s Desktop can make available locally and free, while avoiding needless duplication of already excellent free/open-source tools.
Scope note: “Complete” here means all premium-gated features explicitly surfaced by the official pricing/comparison/help pages reviewed for the named competitors. It is not a claim that every software product in the market or every historical feature flag has been enumerated.
Research cut: 16 September 2026. Prices are snapshots and should be rechecked before implementation or publication.


How to read this audit
	Label
	Meaning

	PAYWALLED
	Feature exists in a paid tier, DLC, licence, or only after purchasing the product.

	LIMITED FREE
	The free edition exposes the feature with a cap, time limit or restricted mode.

	FREE BASELINE
	A strong free/open-source competitor already offers this capability; DK needs integration/UX/privacy differentiation.

	DK TARGET
	Feature is a plausible requirement for DK’s free/local implementation; not a promise that implementation is trivial.

	CAUTION
	Feature may require privileged drivers, third-party codecs, vendor SDKs, licensed databases, or other constraints.

Free baseline / competitive reality
• Libre Hardware Monitor is free/open source and already exposes a broad sensor baseline.
• HWiNFO itself is free for personal use; DK’s case is zero restrictions, shared integration and no external licensing dependency.
Recommended DK free/local target
□ Local hardware inventory and sensor tree with update-rate controls.
□ Graphs/history retained locally for user-selected duration.
□ CSV/JSON export.
□ Threshold alerts.
□ Shared local sensor API for DK modules.
□ Unlimited overlay/dashboard items.
□ Portable diagnostic report.
□ No telemetry or licence checks.
Implementation cautions
! Some sensor access requires vendor/driver-specific support. Prefer documented APIs and isolate unstable hardware plugins.

Premium / gated feature inventory
• Fan control for motherboard, GPU, AIO and supported external controllers.
• Fixed fan speeds and temperature-based fan curves.
• Use CPU/GPU/HDD/SSD/motherboard/AIO sensor temperatures as control sources.
• Multiple controllers per fan with maximum-output arbitration.
• Switchable fan-control profiles via GUI or hotkeys.
• Hysteresis, temperature averaging and rate limits.
• Synthetic temperatures using mathematical combinations (mean/max/time average/limits).
• System/disk monitoring features bundled with the paid application.
Free baseline / competitive reality
• Fan Control by Rem0o is a strong free competitor; this means DK needs safer hardware support plus integration with game/performance/RGB profiles.
Recommended DK free/local target
□ Multi-point curves, fixed mode, hysteresis, smoothing and step/rate limits.
□ Sensor mixing / synthetic max-average sources.
□ Unlimited named profiles.
□ Per-game/profile switching through shared DK rule engine.
□ Fail-safe handling when sensors disappear or the app crashes.
□ Clear supported-hardware matrix and read-only mode.
Implementation cautions
! Fan writing can be hardware-specific and potentially unsafe. Build hard bounds, fail-safe restore and explicit unsupported states.

Recommended DK free/local target

Premium / gated feature inventory
• Bitsum Dynamic Boost: automatically switch between active and idle power plans.
• Notifications showing when/which process changed the active power plan.
Free baseline / competitive reality
• Process Lasso already leaves ProBalance, Performance Mode, Efficiency Mode, CPU affinities/sets/priorities, I/O/GPU priorities, IdleSaver, timed keep-awake, SMT controls, SmartTrim, profile switching and more free.
Recommended DK free/local target
□ Named local profiles bundling Windows power plan + fan + RGB + controller + overlay settings.
□ Automatic activation on game/app launch, AC/DC state or user hotkey.
□ Process affinity/CPU-set/priority rules with reversible defaults.
□ Process watchdog rules (restart/limit/keep-awake) with clear audit log.
□ Profile-change notifications and history.
□ No exaggerated “boost” claims; show exactly which Windows setting changed.
Implementation cautions
! Do not present priority/affinity changes as guaranteed FPS improvements; expose reversible controls and logs.

Premium / gated feature inventory

• Automatic browser-history privacy cleaning.

• Pro Plus adds Recuva file recovery and Speccy hardware inventory.
Free baseline / competitive reality
• Microsoft Sysinternals Autoruns/Process Explorer and Windows Task Manager provide extremely strong free foundations.
Recommended DK free/local target
□ Startup entries with source/publisher/path, impact and disable/restore.
□ Scheduled tasks/services view with conservative warnings.
□ Process tree, command line, signature/publisher, network usage and file location.
□ Rule history and one-click revert.
□ Optional watchdog / keep-running / affinity rules shared with Profiles.
□ No registry-cleaner or fake “health score” pressure tactics.
Implementation cautions
! Editing services/startup items can break systems. Require clear provenance and restore points/config export for risky changes.



What this means for DK’s Desktop
The best DK requirement is not “copy every premium product.” It is to expose the useful local capability without arbitrary quotas, cloud accounts or entitlement checks, while retaining conservative safety boundaries for hardware, drivers and automation.
• Prefer one shared engine per technical domain (sensor service, input service, LAN pairing, macro engine) so multiple modules do not duplicate privileged background services.
• If an excellent free/open-source product already dominates the category, differentiate through integration, simpler UX and verifiable local-only behaviour rather than claiming the feature itself is novel.
• For all risky actions—drivers, fan control, process rules, disk operations—show exactly what will change and provide an explicit revert path.
